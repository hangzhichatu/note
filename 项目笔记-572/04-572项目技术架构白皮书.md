## 1. 项目概述

### 1.1 项目背景

572 项目是基于达索 3DEXPERIENCE（3DE）平台构建的企业级 PLM（产品生命周期管理）系统，涵盖产品数据管理、工程变更管理、文档管理、审批流程管理、制造数据管理等核心业务领域。

### 1.2 项目定位

- **平台基座**：3DEXPERIENCE R2022x（3DSpace + 3DDashboard + 3DPassport）
- **业务中台**：若依（RuoYi）Spring Cloud 微服务架构，承载审批流程引擎
- **数据总线**：多外部系统集成（MES/SAP/ERP/QMS/标准规范/ESB）
- **扩展机制**：JPO + Spinner + Widget 三层扩展体系

### 2.2 架构设计原则

| 原则 | 说明 |
|------|------|
| **平台原生扩展** | 基于 3DE Spinner 配置而非硬编码，通过配置文件（XLS）定义对象模型 |
| **JPO 代理模式** | 前端 Widget 通过 WAFData → postmethod 路由 → JPO 调用，避免跨域 |
| **流程外置** | 审批流程委托给若依 Spring Cloud 微服务，3DE 专注 PLM 核心业务 |
| **异步解耦** | 接口调用采用异步日志 + 重推机制，失败可追溯可重试 |
| **松耦合集成** | 外部系统通过 REST/SOAP/SFTP 三个标准协议交互，各系统独立部署 |

## 5. 核心功能模块

### 5.1 文档管理

**核心业务：** 技术文档、图样、工艺文件的全生命周期管理。

```
流程：创建文档 → 填写属性 → 关联PBOM → 签入文件 → 发起审批 → 归档
                               │
     ┌─────────────────────────┘
     ├─ 18 种文档子类型（图样、技术单、更改单、分发单...）
     ├─ LAMC_CreateDocument Widget 提供统一创建入口
     ├─ 自动关联型号文件夹目录结构
     ├─ 若依流程引擎驱动审批签字
     └─ 签审通过后自动归档至兰考

关键 JPO：domainObjectAction / LAMC_DocumentTrigger / LAMC_RuoYiRouteDocument
关键 REST：POST /ruoyi/domainAction/create → 创建文档
          POST /ruoyi/domainPolicy/fileSign → 签字审批
```

### 5.2 变更管理

**核心业务：** 工程更改（ECO/ECR/EO）的发起、评估、执行、关闭。

```
变更类型：工程更改申请 (ECR)
         工程更改订单 (ECO)
         工程更改指令 (EO)
         数据发布单

流程：ECR 提出 → 影响分析 → ECO 执行 → EO 落实 → 归档
关键 JPO：LAMC_ChangeManagementJPO / LAMC_ChangeDocManagement
          LAMC_AoChange / LAMC_CAAddAffectedItemTrigger
```

### 5.3 物料/BOM 管理

```
PBOM（工艺BOM）：从 EBOM 转换，用于生产制造
EBOM（设计BOM）：产品设计结构

功能：
  - PBOM 创建/编辑/版本管理
  - EBOM 查询（MES 接口同步）
  - 成品件管理（父节点查询）
  - 物料编码申请

关键 REST：GET /resources/FinshedPart/LAMC/getFinishedPartParent?objectId=xxx
          POST /mesServices/getProductEBOM → MES EBOM 查询
关键 JPO：LAMC_PBOMExtend / LAMC_OEMImportJPO
          LAMC_CodeApplicationInterface（编码申请）
```

### 5.4 审批流程（若依集成）

**核心设计：** 3DE 不内置审批，所有审批流程委托给若依系统。

```
3DE 端 → 文档创建/提升 → 通过 postmethod 路由调用 JPO
  → JPO (LAMC_3DEToProcessEngine) 通过 HttpClient 调若依接口
  → 若依 Activiti 启动流程实例
  → 审批节点跨 Service Task 调用回 3DE（签审/提升/合并PDF）
  → 审批完成 → 兰考归档

Node 标识符机制（BPMN Service Task）：
  domainObjectSign        → 同步签审
  domainObjectSignAsync   → 异步签审
  domainObjectSignNot     → 不提升状态的签审
  taskCompleted           → 任务完成监听
```

### 5.5 供应商管理

```
功能：
  - 供应商入库申请
```

```
  - 查询标准规范（从外部标准系统）

接口：http://192.169.14.138:8088/standard/standard572/
```

### 5.8 接口调用日志

```

【文档创建审批流】
用户创建文档
  → LAMC_CreateDocument Widget
  → WAFData → postmethod → JPO (LAMC_RuoYiiInterface)
  → 若依 /danny/custom/createDocument
  → 3DE domainAction.create
  → 创建 Document 对象 + 签入文件
  → 自动发起若依流程（LAMC_3DEToProcessEngine）
  → 审批完成 → domainPolicy.fileSign → LAMC_RuoYiRouteDocument
  → 归档至兰考（LAMC_ArchiveRest）

【外部系统数据同步】
MES/ERP → 3DE REST 接口
  → 调对应 JPO (LAMC_InterfaceManager / LAMC_DELLmiProductionSystemReference)
  → DomainObject.create / promote / setAttributeValues
  → 矩阵数据库写入

【接口调用日志（容灾关键）】
3DE → 若依 的每次接口调用
  → 若依记录到 ApiLog 表（含请求/响应/状态/耗时）
  → 失败记录可查询、单条重发、批量重推
  → 超时/无响应记录有独立筛选视图
```

### 7.2 容灾与高可用设计

#### 7.2.1 若依端容灾

| 机制 | 实现 | 说明 |
|------|------|------|
| **接口日志** | ApiLog 表 | 所有 3DE 调若依的接口记录持久化 |
| **失败重推** | LAMC_AsyncApiLog Widget | 单条重发 + 批量重推（限流 4s/条）|
| **幂等防重** | requestId 去重 | promote/fileSign 等操作使用临时集合记录 requestId，重复请求直接返回成功 |
| **事务回滚** | ContextUtil.startTransaction / abortTransaction | JPO 操作失败时自动回滚 |

#### 7.2.2 外部系统容灾

| 机制 | 说明 |
|------|------|
| **超时设置** | HTTP 调用统一 15s 超时（connect + read）|
| **异常捕获** | JPO 层 try-catch-finally，异常记录到 System.out |
| **Context 权限沙箱** | `ContextUtil.pushContext/popContext` 每次操作前后提升/恢复权限 |
| **事务边界** | 创建文档等复杂操作使用 `ContextUtil.startTransaction/commitTransaction/abortTransaction` |

#### 7.2.3 平台层容灾

| 层面 | 说明 |
|------|------|
| **3DE 集群** | 3DSpace 可水平扩展，通过反向代理负载均衡 |
| **若依集群** | Spring Cloud 微服务支持多实例部署 |
| **数据库 HA** | MatrixDB 支持热备；MySQL 主从复制 |
| **文件备份** | 3DE 本身的文件版本管理 + SFTP 归档 |

#### 7.2.4 数据恢复

| 场景 | 恢复方式 |
|------|---------|
| 文档误操作 | 3DE 版本历史（版本树回退）|
| 流程异常中断 | ApiLog 查询 → 单条重推 |
| 数据同步失败 | 批量重推定时任务 |
| 配置丢失 | Spinner XLS 文件备份（60+ 个文件）|

### 7.3 安全设计

| 维度 | 实现 |
|------|------|
| **认证** | 3DPassport SSO / OAuth2.0 授权码模式 |
| **鉴权** | 3DE 平台 ACL + Role-Based Access Control + Context Access |
| **接口安全** | REST 接口通过 3DE `getAuthenticatedContext()` 获取认证 |
| **密钥管理** | AK/SK 配置在 enovia.properties，不硬编码 |
| **权限提升** | JPO 中使用 `ContextUtil.pushContext(popContext)` 严格控制作用域 |
