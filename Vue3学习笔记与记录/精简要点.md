## 一问一答

* Q1 : vue3和vue2相比有哪些主要变化
* A1：
  Vue3 的核心改造在于:

  * 响应式系统重构: 使用 `Proxy` 替代 `Object.defineProperty` ,支持对数据索引、动态属性的监听
  * **Composition** ***API***  新增 `setup()` 、`ref`、`reactive` 、`computed()`、`watch` 等函数，逻辑复用灵活。
  * 更好的TypeScript 支持：源码用TS重写，类型推导更完善
  * Fragment、Teleport、Suspense等新特性
  * 自定义渲染器API
* Q2 : Vue3的响应式原理是什么？和Vue2有什么区别
* A2：

  * vue2 基于 `Object.defineProperty` ,只能劫持已存在的属性，无法监听数组索引或新增/删除属性 (需要使用 `$set`)
  * VUE3 : 使用 `Proxy` + `Reflect` 实现响应式:

    ```js
    const obj = reactive({ count: 0 });
    // 自动变成响应式，无需提前声明所有属性
    obj.newProp = 'hello'; // 视图会更新
    ```
* Q3:什么是Composition API 为什么要引入它?
* A3：
  Composition API 是Vue3提供的一组基于函数的API，用于组织和复用逻辑代码
  ***解决的问题*** ：

  * vue2的Option API 在大型组件中逻辑分散，难以维护
  * Mixins存在命名冲突、来源不清晰

  ***核心函数:***

  * `setup()` : 组件入口 ，体大 `data` \ `methods` 等
  * `ref` /  refactive : 创建响应式数据
  * `computed` / `watch` / `watchEffect`
* Q4: `ref` 和 `reactive` 有什么区别？什么时候用哪个？
* A4:

  * ref 适用于基本类型或者对象， 访问方式，如果需要访问值的话，需要从 `.value` 方式使用，响应式的原理是内部使用 `reactive({value:xxx})`包装 ，适用于场景简单、需要在模板和逻辑中共享的变量
  * `reactive` 仅对象(Object,Array,Map) ，使用方式是通过 `.xxx` 的方式直接访问内部值，其响应式原理是使用Proxy包装对象，其适用的场景是直接的复杂对象

  这里补充一些最佳实践的场景，需要记忆: 基本类型适用 ref ，对象/数组适用reactive  ***组件暴露给模板的变量统一使用 `ref` (避免响应式结构丢失)***
* Q5: `watch` 和 `watchEffect` 的区别？
* A5：

  * `watch` :
    显式指定监听数据源(ref/reactive/computed)
    默认懒执行(组件挂载后才监听)
    可以获取**新值和旧值**
    可以支持深度监听（`deep:true`）
  * `watchEffect` :
    自动追踪内部响应式依赖
    **立即执行一次**
    无法获取旧值
    适合"副作用"场景(请求数据)
* Q6：Vue3中如何实现逻辑复用?
* A6:
  通过 **自定义Composition函数(Custom Composable)**,类似React Hooks.
  举例说明：

  ```javascript
  // useCounter.js
  import { ref, computed } from 'vue';

  export function useCounter(initial = 0) {
    const count = ref(initial);
    const double = computed(() => count.value * 2);

    function increment() {
      count.value++;
    }

    return { count, double, increment };
  }
  ```
* Q7 : Vue3的生命周期钩子有哪些变化？
* A7：
  Options API生命周期基本保留 （如：`method` ),但Composition API 中需要 `onXxx` 形式：
  Vue 2 对比 Vue3：
  beforeCreate : `setup()开始 `
  created : `setup()结束`
  beformMount : `onBeforeMount`
  mounted：`onMounted`
  beforeUpdate : `onBeforeUpdate`
  updated : `onUpdared`
  beforeUnmount : `onBeforeUnount`
  unmounted : `onUnmounted`

  注意：`beforeCreate` 和 `created` 在 `setup()` 中合并，无需单独使用。
* Q8 : Vue 3 如何优化性能？
* A8 常见优化手段:

  * 使用 `v-memo` (Vue 3.2++) : 缓存子树，避免不必要的更新。
  * `<script setuo>` 语法糖：编译时优化，减少运行时开销。
  * 合理使用 `v-if` vs `v-show`
  * 列表渲染加 `key` 唯一且稳定
  * 避免在模板中使用复杂表达式子 -> 提取到 `compute`
  * 组件懒加载：`defineAsyncComponent`
  * 利用Tree-shaking ： 只引入需要的API（如 `import {ref} from 'vue'`）
* Q9: `<script setup>` 是什么？有什么优势？
* A9：`<script setup>` 是 Vue 3.2 引入的编译时语法糖，简化 Composition API 组件写法。
  优点:
  自动暴露顶层变量/函数给模板（无需 `return`）
  更少样版代码
  更好的TypeScript支持
  编译为高效代码（等价于 `setup()`

  ```vue
  <script setup>
  import { ref } from 'vue';
  const count = ref(0);
  const inc = () => count.value++;
  </script>

  <template>
    <button @click="inc">{{ count }}</button>
  </template>
  ```
* Q10: Vue3还兼容Vue2的写法吗？
* A10：兼容
