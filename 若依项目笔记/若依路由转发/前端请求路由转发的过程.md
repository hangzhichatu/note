## 若依架构-请求转发

* 1.微服务架构中的角色 在若依微服务版本中，通常有三个核心组件：

  * Nacos 服务注册中心 + 配置中心
  * ruoyi-danny（业务服务） 这个模块启动的时候会把自己的IP+端口+服务名称注册到Nacos上面
  * ruoyi-gateway（网关） 收到请求后去Nacos查询 `ruoyi-danny` 模块在哪里然后转发
* 2.完整的的请求转发流程

  * 步骤1 `ruoyi-danny` 启动并且注册自己
    * 在 `ruoyi-danny` 模块的bootstrap.yml配置文件里

      ```yaml
      spring:
        application:
          name: ruoyi-danny          # ← 服务名
      server:
        port: 9201                   # ← 自己的端口（比如 9201）
      spring:
        cloud:
          nacos:
            discovery:
              server-addr: ruoyi-nacos:8848
      ```

      配置配置了注册的服务名称和端口号，它会在Nacos服务列表里面创建一个条目
  * 步骤2 前端请求到达Gateway ，比如这样一个get 的请求

  ```
  /danny/task/list
  ```

  Gateway 匹配到路由：

  ```yaml
  uri: lb://ruoyi-danny   # 注意 lb:// 前缀
  ```
* 步骤3 Gateway 动态查询Nacos
* Spring Cloud Gateway 内置了 **LoadBalancer 客户端**
* 看到 `lb://ruoyi-danny`，就会自动：

  1. 向 Nacos 发起查询：“`ruoyi-danny` 的所有可用实例有哪些？”
  2. Nacos 返回：`[192.168.1.100:9201]`
  3. LoadBalancer 选择一个实例（默认轮询或随机）
  4. 把请求转发过去：`http://192.168.1.100:9201/task/list`

## 核心三组件内容架构

* 架构图

```text
前端浏览器
     │
     ▼
[ ruoyi-gateway ] ←──┐
     │                │
     ▼                │  查询服务位置
[ Nacos 注册中心 ] ◄───┘
     ▲
     │ 注册自己（IP+端口+服务名）
[ ruoyi-danny ]（业务微服务）
```


所有通信都围绕 **Nacos** 展开：业务服务 → **注册自己** 到 Nacos 、 网关 → **发现服务** 从 Naco
