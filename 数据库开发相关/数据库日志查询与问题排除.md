## 数据库的日志查询

* 前置准备，确认日志配置

  ```sql
  -- 查看错误日志文件路径
  SHOW VARIABLES LIKE 'log_error';

  -- 查看慢查询日志是否开启及路径
  SHOW VARIABLES LIKE 'slow_query_log';
  SHOW VARIABLES LIKE 'slow_query_log_file';

  -- 查看通用日志（生产环境通常关闭，因为性能损耗大）
  SHOW VARIABLES LIKE 'general_log';
  SHOW VARIABLES LIKE 'general_log_file';

  -- 查看 Binlog 配置
  SHOW VARIABLES LIKE 'log_bin';
  SHOW VARIABLES LIKE 'binlog_format';
  SHOW MASTER STATUS; -- 查看当前正在写入的 binlog 文件名和位置
  ```

## 具体查看方法

* 1.错误日志
  **作用** **：记录数据库启动、停止、崩溃、主从复制错误、死锁检测等信息。****排查数据库起不来或突然宕机的首选**
  在linux服务器里面 ，查看 log文件的内容（这部分可以参考以下语句来快速查询代码）

  ```txt
  # 假设路径是 /var/log/mysql/error.log，请根据 SHOW VARIABLES 的结果替换路径

  # 查看最后 100 行（实时排查最新错误）
  tail -n 100 /var/log/mysql/error.log

  # 实时滚动查看（像看电影一样看日志生成）
  tail -f /var/log/mysql/error.log

  # 搜索特定关键字（如 "Deadlock" 或 "Abort"）
  grep -i "deadlock" /var/log/mysql/error.log

  ```
* 2.慢查询日志 (Slow Query Log) —— **优化性能必备**

  * **作用** **：记录执行时间超过** `long_query_time`（默认 10 秒）的 SQL 语句。用于找出拖慢系统的“元凶”。
  * 文件格式，纯文本(但格式较乱，通常配合工具分析)**原 始查看****：**`tail -f /path/to/slow.log`

    ```txt
    # 按执行时间排序，列出前 10 条最慢的 SQL
    mysqldumpslow -s t -t 10 /var/log/mysql/slow.log

    # 按返回记录数排序
    mysqldumpslow -s r -t 10 /var/log/mysql/slow.log

    # 忽略数字差异（把 select * from t where id=1 和 id=2 归为一类），按出现次数排序
    mysqldumpslow -a -s c -t 10 /var/log/mysql/slow.log
    ```
* 3.二进制日志 (Binlog) —— **数据恢复与主从复制**

  * 作用，**记录所有修改数据的操作（INSERT, UPDATE, DELETE, DDL）。用于****时间点恢复 (PITR)** **和**  **主从同步** **。**
  * 必须使用 mysqlbinlog 工具查询
  * **文件格式** **：** **二进制格式** **，不能直接用** `cat` **或** `vim` **查看，否则是乱码。**

  ```txt
  # 查看某个 binlog 文件的内容
  mysqlbinlog /var/log/mysql/binlog.000001

  # 只查看特定时间段的数据（例如误删数据恢复时）
  mysqlbinlog --start-datetime="2026-03-23 10:00:00" --stop-datetime="2026-03-23 10:05:00" /var/log/mysql/binlog.000001

  # 将解析出的 SQL 导出到文件
  mysqlbinlog /var/log/mysql/binlog.000001 > recovery.sql
  ```

  *注意：如果开启了 `binlog_format=ROW`，输出的 SQL 会是 `BINLOG` **开头的编码串，需要去掉** `--base64-output=DECODE-ROWS -v` **参数才能看到模拟的 SQL 语句***

## 死锁问题查询

* 一般这种信息都是放在

  ```pgsql
  SHOW ENGINE INNODB STATUS;
  ```
* **操作技巧****：执行后，输出内容非常长。请在结果中搜索**`LATEST DETECTED DEADLOCK` **关键字。**
* **内容解读****：它会告诉你：**

  1. **哪个事务持有什么锁。**
  2. **哪个事务在等待什么锁。**
  3. **导致死锁的具体 SQL 语句。**
  4. **数据库牺牲了哪个事务（回滚了谁）。**

| 日志类型      | 核心用途                 | 查看工具/命令                         | 生产环境建议                 |
| :------------ | :----------------------- | :------------------------------------ | :--------------------------- |
| 错误日志      | 崩库、启动失败、主从断裂 | `tail -f`,`grep`                  | 必须开启，定期轮转           |
| 慢查询日志    | 性能优化、抓慢 SQL       | `mysqldumpslow`,`pt-query-digest` | 建议开启，阈值设合理 (如 1s) |
| Binlog        | 数据恢复、主从同步       | `mysqlbinlog`                       | 必须开启 (若需备份/主从)     |
| 通用日志      | 审计、调试所有操作       | `tail -f`                           | 平时关闭，仅排查问题时临时开 |
| InnoDB Status | 死锁、事务等待           | `SHOW ENGINE INNODB STATUS`         | 随时可查 (内存数据)          |
