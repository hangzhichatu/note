## Netty

* 严格来说Netty并不是一个独立功能的中间件，它是取代原生java网络工程（入BIO）的
* 它的特定是异步与事件驱动:Netty所有的I/O操作都是异步的，当一个操作 **不会立刻完成而是Netty会返回一个ChannelFuture对象**  可以通过给它添加监听器 `ChannelFutureListener` 在操作完成时候自动调用 **执行预设的逻辑，这样就不会阻塞线程的调用了。**

2. 关注点分离与模块化: Netty通过责任链模式设计了ChannelPipeline，可以把不同的功能封装成`ChannelHandler` 并且按照你期望的顺序添加到Pipeline中，使每个组件功能单一，易于维护和复用
3. 高性能和低延迟， Netty使用`EventLoopGroupe`（事件循环组）来处理 IO事件，每个 `EventLoopGroup` 都绑定一个线程，它负责处理多个Channel上的所有IO事件减少了上下文切换的开销，实现了串行无锁化设计，提升了性能。其次就是利用了零拷贝的技术Netty使用了`ByteBuf`和`FileRegion`等技术，尽可能减少数据在内存中的拷贝次数，尤其在大文件传输过程可以显著提高性能。
4. 健壮性与易用性:Netty内置了心跳检测(`IdleStateHander`)、TCP粘包拆包处理器，帮助开发者构建更稳定可靠的网络应用，同时提供了丰富的文档和示例。

### Netty和传统网络编程的对比

| 维度特性 | 传统BIO(Blocking I/O)                                 | Netty基于（NIO）                                            |
| -------- | ----------------------------------------------------- | ----------------------------------------------------------- |
| 线程模型 | 连接线程1：1，一个连接独占一个线程                    | Reactor多路复用:少量线程处理大量连接                        |
| I/O模型  | 同步阻塞:读写操作时候会一直等待                       | 同步非阻塞:线程只在通道有数据时才处理，否则执行其他通道任务 |
| 拓展维度 | 差:线程数随着连接数增长而增加，容易因为资源问题而崩溃 | 强：单机可支持数万甚至数百万的<br />连接触                |
