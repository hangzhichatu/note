## 题目:二叉树的最近公共祖先 (236)

- 题目描述：给定一个二叉树，找到该树中两个指定节点的最近公共祖先（LCA）。
- 最近公共祖先的定义：对于有根树 T 的两个节点 p、q，最近公共祖先表示为一个节点 x，满足 x 是 p、q 的祖先且 x 的深度尽可能大（一个节点也可以是它自己的祖先）。

---

### 核心解法：后序遍历 + 分治（自底向上）

```java
class Solution {
    public TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {
        // 1. 递归终止条件：当前节点为空，或等于 p / q，直接返回当前节点
        if (root == null || root == p || root == q) {
            return root;
        }

        // 2. 后序遍历：先递归左右子树（自底向上找）
        TreeNode left = lowestCommonAncestor(root.left, p, q);
        TreeNode right = lowestCommonAncestor(root.right, p, q);

        // 3. 核心判断：左右都非空 → p、q 分居当前节点两侧 → 当前节点就是 LCA
        if (left != null && right != null) {
            return root;
        }

        // 4. 只有一侧有结果：p、q 都在那一侧，或已在上层找到 LCA → 返回非空侧
        return left != null ? left : right;
    }
}
```

**思路分析：**

为什么用**后序遍历**？因为找"最近"公共祖先必须**自底向上**，先看叶子层，第一个出现"p、q 分居两侧"的节点就是最近的。

每一层递归的返回值语义（关键）：
- `null` → 以当前节点为根的子树里**没有 p 也没有 q**
- `非 null` → 子树里**找到了 p 或 q，或本身就是 LCA**
- 具体是啥：如果子树里只找到 p，返回 p；只找到 q，返回 q；找到 LCA，返回 LCA

**为什么 `left != null && right != null` 时当前节点就是 LCA？**

p、q 分别在当前节点的左子树和右子树，说明当前节点是它们的公共祖先，而且这是**从上往下第一个分叉点**（后序遍历从下往上第一个判定点），所以必然"最近"。

**两种情况走第 4 步（只有一侧非空）：**
1. p、q 都在同一棵子树 → 返回那侧（那侧递归已经算出 LCA 或找到了 p/q）
2. p 是真的、q 在另一侧但不在当前子树 → 返回非空侧，让上层继续判断
3. 两侧都 null → 返回 null（当前子树没有 p 也没有 q）

**边界：p 和 q 互相是祖先后代关系**
- 如果 p 是 q 的祖先，递归到 p 时 `root == p` 直接返回 p，根本不会往下找 q
- 此时另一侧返回 null，走第 4 步返回 p —— 结果正确，p 就是 LCA
- 这是**终止条件 `root == p || root == q` 的设计精妙之处**：遇到目标节点直接短路返回

**复杂度：**
- 时间复杂度：O(n)，每个节点最多访问一次
- 空间复杂度：O(h)，h 为树高（递归栈深度），最坏 O(n)（单链表树）

### 犯错记录 / 面试注意点

1. **为什么不用遍历找路径再比较？**（朴素做法）先分别找 root→p、root→q 的路径，再找两条路径最后一个公共节点。需要额外 O(n) 空间存路径，且代码更啰嗦。后序遍历一次到位更优。
2. **必须自底向上**：如果自顶向下找第一个"两棵子树各含 p/q"的节点，逻辑复杂且易错；后序遍历天然自底向上，代码最简洁。
3. **`root == p` 短路的意义**：遇到 p/q 直接返回，不做多余递归，是性能优化也是 LCA=自身 情况的关键。
4. **返回值语义要讲清**：面试时一定要说明"每个节点返回的是什么"，否则容易逻辑混乱。
