## 环形链表
* 题目描述:
    给你一个链表的头节点 head ，判断链表中是否有环。

    如果链表中有某个节点，可以通过连续跟踪 next 指针再次到达，则链表中存在环。 为了表示给定链表中的环，评测系统内部使用整数 pos 来表示链表尾连接到链表中的位置（索引从 0 开始）。注意：pos 不作为参数进行传递 。仅仅是为了标识链表的实际情况。

* java实现:
    ```java
    /**
    * Definition for singly-linked list.
    * class ListNode {
    *     int val;
    *     ListNode next;
    *     ListNode(int x) {
    *         val = x;
    *         next = null;
    *     }
    * }
    */
    public class Solution {
        public boolean hasCycle(ListNode head) {
            //从环的特点来讨论 .next对象无限存在 ，所以可以利用这个特性，当next次数超过链表长度时候即可判断存在环
            //也可以这样考虑不存在环的树（把队列当作是一种特殊的树）如果边的数目超过节点数目减1那么说明存在环
            //考虑1当前数据结构能否获取数组长度 
            //结论1 不能满足要求无法直接获取数组长度那么前两种想法就无法实现了
            //笨方法呢？记录访问过的节点，直到出现重复节点或者next为空？
            //可行，但是时间复杂度高（初步判断为n平方级别），先考虑有没有其他方法
            //那靠空间换时间呢？用一个set对象存放已经遍历过的数组如果某次添加next对象后set数组长度没变，则说明存在环
            //感觉可行，时间复杂度和空间复杂度都是n级别的，应该可以接受
            //再想想，如果用两个指针操作呢？一个每次next两次，另外一个每次next一次，经历最小公倍数后若 next为两者相同则说明有环，条件成立 
            //声明两个指针

            // 1. 边界条件处理：空链表 或 只有一个节点的链表，不可能有环

            //ai再实现后的ai review反思，前面太多自我感动式的所谓思考，代码里面守卫部分的判断条件要再while里面直接
            //就判断好，实现类似快速失败的逻辑,而不是到循环里面进行补救式的空指针判断。代码习惯很差自我感觉还挺好，严厉自我批评，这种习惯会阻碍你的发展

            if (head == null || head.next == null) {
                return false;
            }
            // 2. 初始化指针
            // 技巧：可以让慢指针从头开始，快指针从头的下一个开始
            // 或者都从头开始，但在循环里先移动再判断（推荐后者，逻辑更统一）
            ListNode slow = head;
            ListNode fast = head;

            // 3. 循环条件：快指针及其下一个节点不能为空
            // 因为 fast 每次要走两步，所以必须检查 fast 和 fast.next
            while (fast != null && fast.next != null) {
                slow = slow.next;          // 慢指针走 1 步
                fast = fast.next.next;     // 快指针走 2 步

                // 4. 判断相遇：必须比较对象引用 (==)，而不是值 (.val)
                if (slow == fast) {
                    return true; // 相遇说明有环
                }
            }

            // 5. 快指针走到尽头，说明无环
            return false;
            
            
        }
    }
    ```
