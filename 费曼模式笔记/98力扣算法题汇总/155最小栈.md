# 155. 最小栈（Medium）

- 题目描述：设计一个支持 `push`、`pop`、`top`、`getMin` 操作，且**能在常数时间 O(1) 内检索到最小元素**的栈。
- 关键约束：只要求栈本身语义，但 **`getMin()` 必须 O(1)**，否则用普通栈 + 遍历就能做（O(n)），没有意义。

---

### 核心解法：辅助栈（O(1) / O(n)）

```java
class MinStack {
    private Deque<Integer> stack;      // 主栈：存所有数据
    private Deque<Integer> minStack;   // 辅助栈：记录历史最小值
    public MinStack() {
        stack = new ArrayDeque<>();
        minStack = new ArrayDeque<>();
    }

    public void push(int value) {
        stack.push(value);
        // 只有 value 是"新最小值"才压入辅助栈
        // 用 <= 而不是 <：处理相同最小值重复出现的情况（见下方易错点）
        if (minStack.isEmpty() || value <= minStack.peek()) {
            minStack.push(value);
        }
    }

    public void pop() {
        int popped = stack.pop();
        // 弹出的恰好是当前最小值，辅助栈同步弹出
        // 用 ==：Integer 小整数缓存/引用比较的坑，见易错点 3
        if (!minStack.isEmpty() && popped == minStack.peek()) {
            minStack.pop();
        }
    }

    public int top() {
        return stack.peek();
    }

    public int getMin() {
        return minStack.peek();  // 辅助栈栈顶就是当前最小值
    }
}
```

**思路分析（为什么用双栈）：**

一个栈想同时做到"先进后出"和"随时 O(1) 取最小值"是矛盾的——最小值会被新元素盖住，取时又回不到历史。所以用**两个栈各司其职**：

```
stack    ：装所有元素，管 pop/top（先进后出）
minStack ：只装"历史最小值序列"，管 getMin（栈顶永远是当前最小值）

① push(v)：
   - stack.push(v)
   - v <= 当前最小值 → minStack.push(v)
     （否则不压，因为新最小值没变，取历史时仍能拿到）
   - 结果：minStack 从栈底到栈顶"非递增"，栈顶=当前最小
② pop()：
   - stack 弹掉 v
   - v == minStack 栈顶 → minStack 也弹掉（因为那个最小值已随主栈元素离开而失效）
③ getMin()：直接看 minStack 栈顶
```

关键在 **minStack 只记录"最小值更新的历史"**，不是每个元素都压——这样取值 O(1) 且省空间。

---

### 💡 核心思路一句话

**`minStack` 维护的是一个随着入栈不断收敛的"最小值历史栈"，`stack` 弹到什么值，`minStack` 就回溯到对应的历史最小值。**

典型过程：
```
push 3 -> stack[3]      minStack[3]        (3是首个，压)
push 5 -> stack[3,5]    minStack[3]        (5>3 不改)
push 2 -> stack[3,5,2]  minStack[3,2]      (2是新的最小值，压)
getMin -> 2                                 (minStack栈顶)
pop    -> 弹2，2==minStack栈顶2，同步弹 -> minStack[3]
getMin -> 3
```

### ⚠️ 手撕易错点

1. **`push` 用 `<=` 而不是 `<`**：
   ```java
   // ❌ 如果用 <，且连续入两个相同最小值 [2, 2]
   // push 2a: minStack [2a]
   // push 2b: 2b < 2 为false，不压 → minStack里只存了一个2
   // pop 掉一个 2（2b 后入先出）: popped==2 弹掉栈顶 → minStack 空!
   // 此时 getMin 报错（peek空栈）
   // ✅ 用 <=：两个2都压入，pop时一个对应一个，安全
   ```
   所以**相同的重复最小值也要各自压一份**，pop 时才能正确减配。

2. **`pop` 时先取 `popped` 再比较**：要拿"被弹出的值"去和 minStack 栈顶比，必须 `int popped = stack.pop()` 先存下来；不能 `stack.pop()` 后又 `stack.peek()` 比较（那拿到的是新的栈顶，逻辑就错了）。

3. **`Integer` 比较的坑——`==` 对吗？**
   这是 **Java 特有陷阱**，面试手撕最容易栽：
   - 本题主栈存的是 `Integer`（引用类型），`popped == minStack.peek()` 比较的是**引用地址**，不是值！
   - 但**为什么这里能跑过**？因为 -128~127 之间的 Integer 走缓存池，`valueOf` 返回同一个对象，所以 [-128,127] 的值 `==` 恰好等价于值相等；**一旦超出这个范围（如 push 128、push 1000）就会比较失败**，导致 minStack 该弹不弹，getMin 出错！
   - **正确写法**：`Objects.equals(minStack.peek(), popped)` 或 `int v = minStack.peek(); if (popped == v)`（先用一个 `int` 基础类型接收，自动拆箱后就是值比较）。
   - ✅ 你的代码里 `value <= minStack.peek()` / `popped == minStack.peek()`，在题目值域（int 任意）下**严格说不稳**，建议改成 `popped == minStack.peek()` 前先拆箱，或统一用 `Objects.equals` 保底。**这是本题最值得记住的隐藏考点。**

4. **`==` 语义在更小值（如 push 数万个不同的逆序值）时会错过同步弹出**，结果 getMin 返回陈旧值——表面不报错，但结果错误，比抛异常更隐蔽。

### 复杂度
- 时间 O(1)：push/pop/top/getMin 全部常数
- 空间 O(n)：辅助栈在最坏情况下（严格递减输入，每个元素都是新最小值）与主栈同规模

### 同类题延伸 / 面试追问

**为什么用两个栈？能只用一个栈吗？**
- 可以，但要用 **差值法**：`stack` 里存 `value - min`（当前值与历史最小值的差），`min` 用一个变量维护。pop 时若差值为负说明弹的是最小值，需回溯 `min = min - 差值`。省一个栈，但代码理解和调试难度更高，面试可提一句作为空间优化思路。
- **本题双栈法**是最直观、最好写、最不易错的标准解，面试首选。

**和 20 有效的括号的联系**：都是"用额外结构记录主结构无法直接表达的信息"——括号用栈存匹配信息，最小栈用辅助栈存最小值轨迹。**"辅助栈 = 为每个核心操作打补丁"**是这一类题的共同抽象，和你在 `00算法解题方法论.md` 里总结的"选数据结构 + 组合互补"完全对得上（栈管顺序 + 辅助栈管极值，两个结构互补）。
