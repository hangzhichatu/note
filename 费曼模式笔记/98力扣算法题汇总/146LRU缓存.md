## 题目:LRU 缓存 (146)

- 题目描述：设计和实现一个 LRU（最近最少使用）缓存。支持 `get` 和 `put` 操作，且两个操作的平均时间复杂度都必须是 **O(1)**。
  - `get(key)`：key 存在返回 value，否则返回 -1
  - `put(key, value)`：key 存在则更新值；不存在则插入。若容量满，先**淘汰最久未使用**的 key。

---

### 数据结构选型（核心：为什么是"哈希表 + 双向链表"）

| 需求 | 数据结构 | 说明 |
|------|---------|------|
| O(1) 定位任意 key | **HashMap** | `Map<key, Node>`，拿 key 直接 O(1) 找到节点 |
| O(1) 知道"最久未使用" / 维护访问顺序 | **双向链表** | 头 = 最近使用，尾 = 最久未使用 |

**设计哲学——两个数据结构互补，各管一件事：**
- **HashMap** 管"快速定位"：O(1) 找 key 对应的节点（它没有顺序概念）
- **双向链表** 管"访问顺序"：头尾即 LRU 语义（它不能按 key 快速定位）
- 二者通过**共享的 key** 形成逻辑一一映射：HashMap 拿 key 定位节点，节点拿 key 反查并删除 map 项

**为什么节点必须存 key？**
容量满时要淘汰尾部节点 `removeTail()` → 摘出链表后，必须同步从 HashMap 删除该项 → 删 map 需要 key，而链表节点不存 key 就无从反查删除 → **节点里冗余存 key 是"双结构同步"的关键**（链表节点作为 map 删除的凭证）。

**为什么用双向不用单向？**
O(1) 摘除一个节点需要知道它的前驱。单向链表要 O(1) 删除必须从头遍历找前驱（O(n)）；双向链表每个节点带 prev，摘除 O(1)。这是保证所有操作 O(1) 的必然选择。

---

### 完整实现（含伪头尾哨兵节点）

```java
class LRUCache {
    // 双向链表节点：必须带 key（供淘汰时反查删除 map）
    class DLinkedNode {
        int key;
        int value;
        DLinkedNode prev;
        DLinkedNode next;
        public DLinkedNode() {}
        public DLinkedNode(int key, int value) {
            this.key = key;
            this.value = value;
        }
    }

    private Map<Integer, DLinkedNode> cache = new HashMap<>();
    private int size;
    private int capacity;
    private DLinkedNode head, tail;    // 伪头尾哨兵，避免空指针边界判断

    public LRUCache(int capacity) {
        this.capacity = capacity;
        this.size = 0;
        // 必须用 this.head / this.tail！否则是同名局部变量遮蔽（见犯错记录）
        this.head = new DLinkedNode();
        this.tail = new DLinkedNode();
        this.head.next = this.tail;
        this.tail.prev = this.head;
    }

    public int get(int key) {
        DLinkedNode node = cache.get(key);
        if (node == null) return -1;
        moveToHead(node);     // 访问过 → 移到头部标记最近使用
        return node.value;
    }

    public void put(int key, int value) {
        DLinkedNode node = cache.get(key);
        if (node != null) {
            node.value = value;
            moveToHead(node);
        } else {
            node = new DLinkedNode(key, value);
            cache.put(key, node);
            addToHead(node);           // 新增节点必须插入链表头！
            size++;
            if (size > capacity) {     // 容量满 → 淘汰最久未使用（尾）
                DLinkedNode res = removeTail();
                cache.remove(res.key); // 靠节点的 key 同步删除 map
                size--;
            }
        }
    }

    private void moveToHead(DLinkedNode node) {
        removeNode(node);
        addToHead(node);
    }

    // 摘除节点：前一个指向后一个，后一个指向前一个（O(1)）
    private void removeNode(DLinkedNode node) {
        node.next.prev = node.prev;
        node.prev.next = node.next;
    }

    // 插入头节点（head 之后）
    private void addToHead(DLinkedNode node) {
        node.next = head.next;
        node.prev = head;
        head.next.prev = node;
        head.next = node;
    }

    // 淘汰尾部最久未使用节点
    private DLinkedNode removeTail() {
        DLinkedNode res = tail.prev;
        removeNode(res);
        return res;
    }
}
```

**复杂度：**
- 时间复杂度：get / put 均 O(1)（HashMap O(1) + 链表 O(1)）
- 空间复杂度：O(capacity)，存储所有键值

### 犯错记录 / 面试注意点

1. **构造器 `head`/`tail` 必须 this（致命 bug）**：
   `DLinkedNode head = new DLinkedNode()` 是局部变量，遮蔽了成员变量 `head`。成员变量仍是 null，`head.next` 一调用就 NPE。**根因不是"访问私有属性必须 this"，而是"同名遮蔽必须 this"。**（重命名局部变量或加 this 均可）

2. **新增节点忘了 addToHead（致命 bug）**：
   新增分支只 `cache.put` + `size++`，漏了把节点插入链表。导致链表和 map 不同步，后续 get 到的节点不在链表里，moveToHead 的 removeNode 操作的是错误链路。

3. **get 也算一次访问**：没命中返回 -1 不动链表；命中必须 moveToHead。

4. **put 更新已有 key**：直接改 value + moveToHead，不增加 size、不触发淘汰。

5. **哨兵节点的作用**：head/tail 是占位节点，避免链表为空时 deal null 的边界分支，让 addToHead/removeTail 统一成立。

6. **removeNode 本身没错**：`node.next.prev = node.prev; node.prev.next = node.next;` 是标准的双向摘除，出错往往是因为链表根本没同步好（见 1、2）。

### 设计哲学提炼（面试加分）

- **互补结构各司其职**：哈希表管"定位"，链表管"顺序"，互不越权，靠 key 同步。
- **互存引用 vs 共享 key**：链表内部节点间用互存 prev/next 引用（结构内）；HashMap 与节点之间用共享 key（结构间）——因 map 和链表是两个独立索引，无需也不该互持引用。
- **为什么节点冗余存 key**：让链表在淘汰时能反查删除 map 对应项，这是双结构同步的凭证。
