# 215. 数组中的第 K 个最大元素（Medium）

- 题目描述：在未排序的数组中找到第 k 个最大的元素。例：[3,2,1,5,6,4]，k=2 → 返回 5。

---

## 解法一：最小堆（Boss 主解法 ✅ 已通过）

**思路：** 维护一个**大小为 k 的最小堆**（优先队列）。遍历数组：
- 堆未满（< k）直接入堆
- 堆已满，若当前元素 > 堆顶：弹出堆顶，入堆
- **堆顶始终是"当前已见的第 k 大"**，遍历完返回堆顶即可

```java
public int findKthLargest(int[] nums, int k) {
    PriorityQueue<Integer> minHeap = new PriorityQueue<>(); // 默认小顶堆
    for (int num : nums) {
        minHeap.offer(num);
        if (minHeap.size() > k) {
            minHeap.poll();   // 超过 k 个就踢掉最小（堆顶）
        }
    }
    return minHeap.peek();
}
```

**为什么最小堆对"重复元素"免疫？**
- 堆不依赖"枢轴划分"，只是维护"当前最大的 k 个"
- 重复元素（如 10000 个 1）对堆没有任何影响，只是正常进出
- → **天然免疫重复元素退化** | 复杂度 O(n log k)

> 面试话术："用大小为 k 的最小堆，堆顶就是第 k 大。重复元素对堆无影响，稳定 O(n log k)。"

## 解法二：随机化快速选择（Boss 尝试，重复数据超时）

**思路：** 快排的变种。目标下标 = `nums.length - k`。每次 partition 后：
- `pivotIndex == target` → 返回
- `pivotIndex < target` → 去右边 `[pivotIndex+1, right]`
- `pivotIndex > target` → 去左边 `[left, pivotIndex-1]`

平均 O(n)，最坏 O(n²)。

### ⚠️ 超时原因（重要教训）

Boss 用 `-1,-2,-3,-4,-5,0,2,3,4,5` + **10000 个重复的 `1`** 测试时超时。原因有两个：

**① `new Random()` 每次新建（Bug）**
```java
// ❌ partition 每次调用都 new，同一毫秒内随机种子相同 → 随机序列重复 → 随机化失效
int randomIndex = left + new Random().nextInt(right - left + 1);
```
修复：提为**成员变量** `private Random random = new Random();`，只 new 一次。

**② 重复元素 + `<=` 单向堆积（数据退化，修好 Random 也救不了）**
```java
if (nums[i] <= pivot) {   // <= 把所有等于 pivot 的往左塞
```
- 10000 个重复 `1`，若 pivot 是 `1` → 10000 个 `1` **全堆到左侧**
- 分区极度不平衡 → 每次只排除少量元素 → 退化为 **O(n²) 超时**
- **这是二路快排 + 大量重复值的经典反例**（LeetCode 215 专门有这类卡数据）

> ⚠️ 补充：注释曾写反（`pivotIndex < target` 去右边 被标成"左边"）。代码方向对，注释反。`pivotIndex < target` → 目标在枢轴**右**侧，去右边。

## 解法三：三路快排（进阶加分项 ⭐ 可选）

**解决思路：** 把数组分成三段 `<pivot`、`==pivot`、`>pivot`。**`==pivot` 的重复元素单独放中间段，递归时整段跳过**，从根本上消除重复元素退化。

**核心思想一句话：**
> "三路快排 = 普通快排 + 把等于 pivot 的元素放中间段，下次递归直接跳过这一段"

**为什么对重复元素有效：**
- 10000 个重复 `1` 全进 `==pivot` 段
- 若目标落在这段 → **一次性命中，整个重复段完全不递归**，O(1) 处理
- 从 O(n²) 拉回平均 O(n)

**三指针（荷兰国旗问题）：**
```java
int lt = left;      // lt 左 = < pivot
int i = left + 1;   // 扫描员
int gt = right;     // gt 右 = > pivot
while (i <= gt) {
    if (nums[i] < pivot) { swap(nums, i, lt); lt++; i++; }
    else if (nums[i] > pivot) { swap(nums, i, gt); gt--; }  // i 不++，换来的还没看
    else { i++; }  // == pivot 留在中间
}
```

**面试应对（不要求手写也能加分）：**
> "最小堆天然免疫；如果坚持用快排，重复元素会让二路 partition 退化，可用三路快排把等于 pivot 的放中间段整体跳过。"

**Boss 手写实现（2026-08-30 已验证理解 ✅）：**
```java
private int[] partition(int[] nums, int left, int right) {
    int pivot = nums[left];
    int lt = left;      // [left, lt-1] 是小于 Pivot 的区域
    int gt = right + 1; // [gt, right] 是大于 Pivot 的区域
    int i = left + 1;   // [lt, i-1] 是等于 Pivot 的区域

    while (i < gt) {
        if (nums[i] < pivot) {
            swap(nums, ++lt, i++);      // 小 → 换到小于区末尾
        } else if (nums[i] > pivot) {
            swap(nums, --gt, i);        // 大 → 换到大于区开头（i 不自增！换来的没检查）
        } else {
            i++;                        // 等于 → 扩大等于区
        }
    }
    swap(nums, left, lt);              // 把 pivot 放到等于区最左
    return new int[]{lt, gt - 1};     // 返回等于区 [左边界, 右边界]
}
```

**🔑 关键理解：为什么 `gt = right + 1` 不越界？**
- `gt` 存的是"大于区的起点"（开区间边界标记），**不是用来访问的下标**
- 循环中访问数组的始终是 `nums[i]` 和 `--gt` 之后的合法下标
- `--gt` 先自减到 `right` 才 swap → 从此 gt 一直在 `[left, right]` 内，永远合法
- 全程没有任何一行用 `nums[right+1]` 读值 → 不越界
- 金句："`gt=right+1` 只是标记大于区起点=开区间，它不读数组元素，`--gt` 会先自减到合法下标再交换"
- 注：另一等价写法 `gt = right` 是闭区间配套，逻辑稍绕；本版开区间更简洁
