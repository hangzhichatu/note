# 739. 每日温度（Medium）

- 题目描述：给定一个整数数组 `temperatures`，表示每天的温度。返回一个数组 `answer`，其中 `answer[i]` 是指对于第 `i` 天，下一个更高温度出现在几天后。如果气温在这之后都不会升高，请在该位置用 `0` 来代替。

---

### 核心解法：单调栈（存下标！）— O(n) / O(n)

```java
class Solution {
    public int[] dailyTemperatures(int[] temperatures) {
        int n = temperatures.length;
        int[] arr = new int[n];                    // 默认全 0，未找到更高温度的自然为 0
        Deque<Integer> stack = new ArrayDeque<>(); // ⭐ 栈中存储【索引】，不是温度

        for (int i = 0; i < n; i++) {
            // 当前温度 > 栈顶索引对应的温度 → 栈顶日遇到"第一个更高温度"就是今天 i
            while (!stack.isEmpty()
                   && temperatures[i] > temperatures[stack.peek()]) {
                int prevIndex = stack.pop();       // 弹出的是【某天】的下标
                arr[prevIndex] = i - prevIndex;    // 等待天数 = 两个下标的距离
            }
            stack.push(i);                         // 当前索引入栈，等未来更高温度
        }
        return arr;                                // 栈内剩下的永远等不到升温，保持 0
    }
}
```

**思路分析（单调栈的"推平"过程）：**

维护一个温度**从栈底到栈顶严格递减**的栈（栈顶温度最低）。每次来一个高温 `temperatures[i]`：

```
① 只要当前温度 > 栈顶日温度 → 弹出栈顶日，并立刻给它结算答案（i - 它的下标）
   —— 因为它是第一次遇到比自己高的温度，就是今天
② 把所有比当前低的都弹完 → 当前 i 入栈
③ 栈里剩下的（没被弹过）→ 后面再没有更高温 → 答案保持 0
```

每个元素**最多入栈一次、出栈一次** → O(n)。为什么用 while + 递减栈？因为"当前高温"能一次"替"前面所有更凉的日子结账，这就是单调栈压缩重复计算的来源。

### 🐛 Boss 的错误版反向分析（最值钱的记录）

**错误版核心（只存温度 + popTimes 计数）：**
```java
int popTimes = 0;
while(!stack.isEmpty() && currentTemperature > stack.peek()){
    stack.pop();
    popTimes++;
    popTimes2++;
    arr[i - popTimes2] = popTimes;   // ❌ 连续 pop 次数 ≠ 距离！❌
}
stack.push(currentTemperature);
popTimes = 0;
```

**两个连坐的错误（你自己都点出来了）：**

1. **栈里只存了温度** → `stack.pop()` 只知道弹出了"一个温度"，**不知道是第几天的温度** → 丢失了"当天日期/下标"这一维信息。
2. **用 popTimes 记录连续出栈次数** → 但"连续 pop 的次数"**绝对不等于**"距离下一个更高温度的日子"。每个被弹出的天，它的答案（=`i - 下标`）各不相同，根本不能用同一个计数器分配。

**为什么"只有第一次计算能得到正确值"（你的观察）**——深层原因：
- 被弹出的"那个天"这个**实体**，在"只存温度"的方案里**根本不存在**了。你弹的是"温度"，不是一个"带日期的天"。
- 温度只是某一天的**属性**，你却把它当成了**那一天本身** → 一旦弹出，就永久丢失了"它是哪天"。
- 而单调栈恰恰要结算的是"**那天**"的答案 → 没有下标，无从结算。

### 💡 核心感悟（Boss 总结，务必牢记）

> **"不要无理由修改原始数据的格式导致丢信息。正确的做法是利用【下标】入栈，既能算天数差、又能拿到对应天数的温度。把温度入栈就丢失了当天日期这个信息，连锁导致想通过计算得到天数差，但只有第一次计算能得到正确值。"**

**升华成通用原则（同类题的金钥匙）：**

> **当一个问题既需要"比较值"、又需要"计算位置差"时，容器里应存【下标】而非【值】——因为下标是"超集"：它能取回值（`arr[index]`），还能算位置（`i - index`）。而只存值，位置信息就永久丢失，补不回来。**

下标 = 位置信息 + 取值的门票，一举两得。

### 复杂度
- 时间 O(n)：每个元素入栈/出栈各一次
- 空间 O(n)：最坏情况（温度严格递减）所有下标都在栈里
