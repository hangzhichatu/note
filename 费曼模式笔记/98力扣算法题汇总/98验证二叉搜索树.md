## 题目:验证二叉搜索树

- 题目描述：给你一个二叉树的根节点 `root` ，判断其是否是一个有效的二叉搜索树。

- 有效二叉搜索树定义为：
  1. 节点的左子树 **只包含** 小于当前节点的数
  2. 节点的右子树 **只包含** 大于当前节点的数
  3. 所有左子树和右子树自身必须也是二叉搜索树

---

### 解法A：范围递归法（自顶向下）

```java
class Solution {
    public boolean isValidBST(TreeNode root) {
        return validate(root, Long.MIN_VALUE, Long.MAX_VALUE);
    }

    boolean validate(TreeNode node, long min, long max) {
        if (node == null) return true;
        if (node.val <= min || node.val >= max) return false;
        return validate(node.left, min, node.val) 
            && validate(node.right, node.val, max);
    }
}
```

**思路分析：**

反证法思想。假设这是一棵合法的 BST，那么每个节点必然落在特定的数值区间内：
- **根节点**：`(-∞, +∞)`，没有限制
- **左子节点**：`(-∞, 根节点值)`，必须小于父节点
- **右子节点**：`(父节点值, +∞)`，必须大于父节点

把这个区间约束作为参数向下传递，每一层递归根据当前节点值「收紧」区间：
- 往左走，更新上界为当前节点值
- 往右走，更新下界为当前节点值

**为什么用 Long 而不用 Integer？**

节点的值可以是 `Integer.MIN_VALUE` 和 `Integer.MAX_VALUE`。如果用 `int`，`Integer.MIN_VALUE` 就不可能有合法的左子树（因为 `>` 条件的下界就是它本身）。用 `Long.MIN_VALUE` / `Long.MAX_VALUE` 就能规避这个边界问题。

**为什么是 `<=` 和 `>=` 而不是 `<` 和 `>`？**

BST 要求严格大于/小于，不存在相等节点。如果节点值等于边界，说明存在相等值，违反二叉搜索树的严格定义。

**递归的 && 语义：**

`return validate(...) && validate(...)` 是"全能"判断——两棵子树都合法才算合法。Java 的 `&&` 是短路运算符，一旦左子树不合法，右子树直接跳过，实现了隐式的剪枝。

**复杂度：**
- 时间复杂度：O(n)，每个节点恰好访问一次
- 空间复杂度：O(n)，最坏情况（单链表树）递归深度 = n

### 解法B：中序遍历法（自底向上）

```java
class Solution {
    long preVal = Long.MIN_VALUE;

    public boolean isValidBST(TreeNode root) {
        if (root == null) return true;
        if (!isValidBST(root.left)) return false;
        if (root.val <= preVal) return false;
        preVal = root.val;
        return isValidBST(root.right);
    }
}
```

**思路分析：**

利用 BST 的核心性质：**中序遍历的结果一定是严格升序的**。

把验证问题转化为"检查中序遍历序列是否严格递增"，没必要真构造出整个序列，用 `preVal` 记录上一个遍历到的值，每次处理当前节点时跟它比较即可。

**为什么可以写到递归里而不是在外面包一个 inorder 函数？**

利用了递归调用的天然顺序：
1. `isValidBST(root.left)` — 先处理完左子树（中序的前段）
2. 判断当前节点（中序的中间段）
3. `isValidBST(root.right)` — 再处理完右子树（中序的后段）

中序遍历的三个阶段刚好对应递归展开顺序，所以直接在递归函数里操作就可以了。缺点是返回值被"提前返回"占用了，需要额外用成员变量维护 `preVal`。

**边界问题同样用 Long：**

根节点值是 `Integer.MIN_VALUE` 时，`preVal` 初始化为 `Integer.MIN_VALUE` 会导致 `root.val > preVal` 永远为假。用 `Long.MIN_VALUE` 确保第一个节点一定能通过。

**复杂度：**
- 时间复杂度：O(n)，每个节点访问一次
- 空间复杂度：O(n)，递归深度

---

### 两种思路对比

| 维度 | 范围递归法 | 中序遍历法 |
|------|-----------|-----------|
| 核心思想 | 约束向下传递 | 性质逆向验证 |
| 判断依据 | 节点值是否越界 | 序列是否升序 |
| 数据流动 | 参数传递，向下收紧区间 | 成员变量，向上传递前驱值 |
| 边界处理 | Long 类型规避 int 边界 | 同样用 Long 规避 |
| 代码风格 | 纯参数 + 返回，无副作用 | 需成员变量，稍带状态 |
| 适合场景 | 验证类问题通解 | 凡是需要 BST 中序序列的场景都有用 |

### 犯错记录

当用中序遍历法实现时需要注意：
1. **Java 值传递陷阱**：`pre` 作为方法参数传入递归，修改后不对外层可见，必须用成员变量
2. **剪枝**：发现不合法后 `return` 提前终止，别傻乎乎遍历完
3. **相等判断**：是 `<=` 不是 `<`，BST 要求严格升序
