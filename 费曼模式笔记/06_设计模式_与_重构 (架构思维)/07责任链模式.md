## 责任链模式

* 一句话说明白，责任链模式就是参与处理某项事务的节点，在预定条件下还会将调用其他节点来处理，**它允许你将请求沿着处理者链条传递，直到有对象处理它为止。**
* 核心思想是将请求的发送者和接收者解耦，让多个对象都有机会处理请求，流水线上的每个节点都可以决定是自己处理还是传递给下一个节点抑或者两者都做。
* 核心结构，责任链模式包含了以下几个关键角色
  抽象处理者：它定义了一个请求处理的接口，持有对下一个处理的next的引用，用于将请求传递下去
  具体处理中：它实现了抽象处理者的接口**当请求到达时，它判断自己是否能处理。如果能，就处理它；如果不能（或处理完后需要继续），就将请求转发给 **`next`
  客户端，负责创建处理者对象
* 两种模式:
  **纯责任链 (中断链)**:**请求在链条上传递，直到**某一个处理者处理了它，传递便终止。适用场景:多个对象均可以处理请求，但只需要其中一个来处理，比如事件处理器。
  **不纯责任链 (全传递链)**:**请求会**依次经过链条上的每一个处理者，每个处理者都有机会对请求进行处理（如过滤、日志记录等）。适用场景:需要对请求多级、顺序处理。比如WEB过滤器，拦截器，权限校验


* 
* java实现实际案例，员工请假:

  ```java
  // 1. 抽象处理者 (Handler)
  abstract class Approver {
      protected Approver next; // 持有下一个审批人

      public void setNext(Approver next) {
          this.next = next;
      }

      // 处理请求的方法
      public abstract void handleRequest(int days);
  }

  // 2. 具体处理者：组长 (ConcreteHandler)
  class TeamLeader extends Approver {
      @Override
      public void handleRequest(int days) {
          if (days <= 1) {
              System.out.println("组长审批：批准 " + days + " 天假期。");
          } else if (next != null) {
              System.out.println("组长：假期超过1天，转交给经理审批。");
              next.handleRequest(days); // 传递给下一个
          }
      }
  }

  // 3. 具体处理者：经理 (ConcreteHandler)
  class Manager extends Approver {
      @Override
      public void handleRequest(int days) {
          if (days <= 3) {
              System.out.println("经理审批：批准 " + days + " 天假期。");
          } else if (next != null) {
              System.out.println("经理：假期超过3天，转交给总监审批。");
              next.handleRequest(days); // 传递给下一个
          }
      }
  }

  // 4. 具体处理者：总监 (ConcreteHandler)
  class Director extends Approver {
      @Override
      public void handleRequest(int days) {
          if (days <= 7) {
              System.out.println("总监审批：批准 " + days + " 天假期。");
          } else {
              System.out.println("总监：假期超过7天，不予批准。");
          }
      }
  }

  // 5. 客户端 (Client)
  public class Client {
      public static void main(String[] args) {
          // 组装责任链
          Approver teamLeader = new TeamLeader();
          Approver manager = new Manager();
          Approver director = new Director();

          teamLeader.setNext(manager);
          manager.setNext(director);

          // 发起请求：请假5天
          System.out.println("=== 员工申请请假5天 ===");
          teamLeader.handleRequest(5);

          System.out.println("\n=== 员工申请请假0.5天 ===");
          // 发起请求：请假0.5天
          teamLeader.handleRequest(0);
      }
  }
  ```
* 优点**降低耦合度** **：请求发送者无需知道哪个对象会处理请求，处理者之间也相互独立**
* **增强灵活性****：可以动态地改变链内的处理者顺序，或增加/删除处理者，符合****开闭原则****。
* 符合单一职责原则，每个处理者只负责具体一项特定任务，职责清晰。
* 缺点：性能开销，如果链条过长，需要依次遍历可能会影响性能
* 调试困难:请求的处理过程是动态的，追踪请求最终由谁处理可能会比较麻烦
* 可能无人处理:**如果没有设置好链条，请求可能传递到末尾也未被处理。**
