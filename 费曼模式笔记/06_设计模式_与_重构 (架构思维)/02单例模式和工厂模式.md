## 单例模式
* 一句话说明白: 单例模式的类只有一个实例，并提供一个全局访问点，类似生活中的太阳，大家用的应该是同一个实例而不是不同的。
* 单例模式的最佳实践案例，数据库连接池：不能每次都新建连接，太慢了，要全局共享一个池子。日志记录器：所有模块都往同一个日志文件里写，不能开十个文件配置管理器：读取一次配置文件，全局共享。
* 实现方式 懒汉式实现:
    ```java
    public class Singleton {
        // 1. 私有化构造函数：不让别人 new 我
        private Singleton() {}

        // 2. 静态变量：自己创建一个实例（类加载时就创建，所以叫“饿汉”，很急）
        private static final Singleton INSTANCE = new Singleton();

        // 3. 公共方法：提供全局访问点
        public static Singleton getInstance() {
            return INSTANCE;
        }

        public void doSomething() {
            System.out.println("单例正在工作...");
        }
    }
    ```

* 单例模式的核心就是必须要让构造方法私有化，并且提供一个返回实例对象的方法。
* 单例模式的实现类型:
饿汉式：类加载时就创建。线程安全，简单，但可能浪费内存（如果没用到）。
```java
public class SingletonHungry {
    // 1. 类加载时就创建实例（静态变量初始化）
    private static final SingletonHungry INSTANCE = new SingletonHungry();

    // 2. 私有构造函数
    private SingletonHungry() {}

    // 3. 提供全局访问点
    public static SingletonHungry getInstance() {
        return INSTANCE;
    }
}
```

懒汉式：用的时候才创建。需要加锁（synchronized）保证线程安全，但性能稍差。
```java
public class SingletonLazy {
    private static SingletonLazy instance;

    private SingletonLazy() {}

    // 加上 synchronized 关键字，保证线程安全
    // 缺点：每次调用都要竞争锁，效率低
    public static synchronized SingletonLazy getInstance() {
        if (instance == null) {
            instance = new SingletonLazy();
        }
        return instance;
    }
}
```

双重检查锁（DCL）：懒汉式的优化版，性能最好，但代码复杂。

```java
public class SingletonDCL {
    // volatile 关键字：保证指令重排序，防止多线程环境下出错
    private static volatile SingletonDCL instance;

    private SingletonDCL() {}

    public static SingletonDCL getInstance() {
        // 第一次检查：如果实例已存在，直接返回，不进入同步块（高性能的关键）
        if (instance == null) {
            synchronized (SingletonDCL.class) {
                // 第二次检查：进入同步块后，再次确认实例是否存在
                if (instance == null) {
                    instance = new SingletonDCL();
                }
            }
        }
        return instance;
    }
}
```
静态内部类：既线程安全又懒加载，推荐写法。
```java
public class SingletonInner {
    private SingletonInner() {}

    // 静态内部类
    private static class Holder {
        // 只有在 Holder 类被加载时，INSTANCE 才会被初始化
        private static final SingletonInner INSTANCE = new SingletonInner();
    }

    public static SingletonInner getInstance() {
        return Holder.INSTANCE;
    }
}
```

枚举：最简洁，还能防止反序列化破坏单例，大神推荐。
```java
public enum SingletonEnum {
    INSTANCE; // 唯一的实例

    public void doSomething() {
        System.out.println("枚举单例正在工作...");
    }
}
```
  
## 工厂模式
* 一句话说明白，把创建一个对象的复杂逻辑隔离开来，提供一个简单的创建方法入口，只需要传入必要参数就行。
* 代码实现:
    ```java
    // PaymentFactory.java
    public class PaymentFactory {
        
        // 专门负责生产 Payment 的车间
        public static Payment createPayment(String type) {
            if (type.equals("alipay")) {
                // 这里可以放复杂的初始化逻辑
                System.out.println("正在初始化支付宝配置...");
                return new Alipay();
            } else if (type.equals("wechat")) {
                // 这里可以放微信的复杂逻辑
                System.out.println("正在初始化微信证书...");
                return new WechatPay();
            }
            throw new RuntimeException("不支持的支付方式");
        }
    }
    ```
