## List 阵营：不仅仅是 ArrayList
* 除了大家熟知的 ArrayList（数组实现，查快改慢）和 LinkedList（链表实现，改快查慢），中级开发必须掌握的是它的**线程安全变种。**
* **CopyOnWriteArrayList** 一句话解释： 一个“读写分离”的列表，读的时候随便读，写的时候先复制一份再改。层原理（写时复制）： 
    读操作： 无锁，直接读旧数组，速度极快。
    写操作（增/删）： 加锁 -> 复制原数组 -> 在新数组上修改 -> 将引用指向新数组 -> 释放锁。
    优缺点：
    ✅ 优点： 读性能极高，遍历时不会抛出 ConcurrentModificationException（因为遍历的是旧快照）。
    ❌ 缺点： 写操作消耗内存（复制数组）且慢；只能保证最终一致性（写完了别人不一定马上看到）

## 2. Set 阵营：去重的艺术

| 容器 | 核心特性 | 底层实现 | 适用场景 |  
| :--- | :--- | :--- | :--- |  
| HashSet | 无序、不可重复 | `HashMap` | 快速去重，比如统计 UV（独立访客）。 |  
| LinkedHashSet | 有序（插入顺序） | `LinkedHashMap` | 既要去重，又要保持顺序（比如缓存淘汰策略）。 |  
| TreeSet | 排序（自然/自定义） | `TreeMap` (红黑树) | 需要范围查询（如 60-80 分之间的人）或自动排序。 |  

**`TreeSet` 和 `HashSet` 的区别，就像“字典”和“乱序的一堆词”。如果你需要按字母顺序查单词，或者查“A到C开头的所有单词”，就用 `TreeSet`。**

## Queue 阵营：任务调度中心
* 队列不仅仅是先进先出，它是多线程协作的核心。
* `BlockingQueue` (阻塞队列) 一句话解释： 一个“有容量限制”且“会自动等待”的队列。
* 核心机制：
    队列为空时： 消费者（取数据的线程）会阻塞（睡觉），直到有数据进来。
    队列已满时： 生产者（放数据的线程）会阻塞，直到有空位腾出。
    适用场景： 生产者-消费者模型。最典型的就是线程池（ThreadPoolExecutor），任务提交快了，先放队列里慢慢消费。
    常见实现：
    `ArrayBlockingQueue`：有界队列，满了就阻塞，适合控制资源上限。
    `LinkedBlockingQueue`：可选有界（默认 Integer.MAX_VALUE），基于链表，吞吐量通常更高。
* `PriorityQueue` (优先队列) 一句话解释： 不按排队顺序，按“重要程度”出队。底层原理： 堆（Heap）结构。默认是小顶堆（最小的元素先出来）。适用场景： 任务调度（VIP 用户优先处理）、延迟队列（配合 DelayQueue）。

## Map 阵营：键值对的高级玩法
* LinkedHashMap：一句话解释： 一个“记性好”的 HashMap，记得你是什么时候放进去的，或者什么时候访问过它。底层原理： HashMap + 双向链表。两种模式、
      *  插入顺序： 谁先来谁排在前面。
      *  访问顺序： 谁最近被 get 过，谁就排到最后面。
      *  实现 LRU 缓存。利用“访问顺序”模式，当 Map 满了，把链表头（最久没被访问的）删掉。
* TreeMap 一句话解释： 自带排序功能的 Map。
      * 底层原理： 红黑树
      * 特点： 查询复杂度 O(log n)，比 HashMap 慢，但 Key 是有序的。
      * 适用场景： 需要根据 Key 进行范围查找（例如：查找价格 100 元到 200 元之间的所有商品）。
* WeakHashMap  一句话解释： 一个“健忘”的 Map，如果 Key 没人用了，它会自动把条目删掉。底层原理： Key 是弱引用。适用场景： 缓存。比如你缓存了某个对象的属性，当这个对象本身被 GC 回收后，缓存也应该自动消失，防止内存泄漏。


## 避坑指南：Fail-Fast 机制
* 现象： 在 foreach 循环遍历集合时，直接调用集合的 remove() 方法，会抛出 ConcurrentModificationException。
* 原因： 集合在遍历时会检查“修改次数”，发现你偷偷改了结构，为了防止数据不一致，直接报错。
* 解决方案：
      * 使用迭代器的 iterator.remove()。
      * 使用并发容器（如 CopyOnWriteArrayList）。
      * 使用 Java 8 的 removeIf()。

## 对比表格

| 需求 | 推荐容器 | 核心理由 |  
| :--- | :--- | :--- |  
| 线程安全的 List | `CopyOnWriteArrayList` | 读多写少，无锁读取 |  
| 需要去重且有序 | `LinkedHashSet` | 保持插入顺序 |  
| 需要范围查询/排序 | `TreeSet` / `TreeMap` | 红黑树自动排序 |   
| 线程间任务传递 | `BlockingQueue` | 自动阻塞，解耦生产消费 |  
| 实现 LRU 缓存 | `LinkedHashMap` | 维护访问顺序 |  
| 定时/优先级任务 | `PriorityQueue` / `DelayQueue` | 堆结构，按权重出队 |
